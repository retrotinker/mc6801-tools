# Introduction

mc6801-tools is a set of Unix-style development tools for the Motorola
MC6801 and MC6803 microprocessors, and for machines built around them,
such as the Tandy MC-10. They run on Linux and other Unix-like systems.

| Tool | Purpose |
|:-----|:--------|
| `as01` | Assembler: turns MC6801 assembly source into relocatable object modules or absolute binaries |
| `ld01` | Linker: combines object modules and libraries into an executable |
| `ar01` | Archiver: collects object modules into libraries |
| `objdump01` | Displays the contents of executables; also installed as `nm01` and `size01` |
| `objcopy01` | Converts executables into S-records, Intel hex, raw binaries and cassette images |

## Why a linker?

Many 6800-family assemblers are *absolute* assemblers: a program is one
source file (perhaps with include files), assembled at a fixed address
straight into a loadable image. `as01` can work that way too.

Its main strength, though, is *separate assembly*. You can split a
program into modules, each assembled on its own into an object file.
Modules export the symbols they define and import the ones they use.
The linker then joins them, resolves the references between them and
places the whole program at its final address. Commonly used modules
can be kept in libraries, and the linker only includes the ones that a
program actually needs.

## Typical workflow

```
  prog.s --as01--> prog.o --+
  util.s --as01--> util.o --+--ld01--> prog.aout --objcopy01--> .wav .s19 .hex .bin
  a.o b.o --ar01--> libx.a -+              |
                                           +--objdump01--> symbols, sizes, dump
```

## Heritage

The tools come from the MC6809 configuration of the assembler, linker
and archiver in Bruce Evans' C compiler (`bcc`), as maintained in the
*dev86* package for Linux (<https://github.com/lkundrak/dev86>). They
have been adapted for the MC6801 instruction set.

The assembler syntax follows the one described in section C.5 of the
*Introl-C Compiler Reference Manual*. The object file format is the
*Introl Linkable Binary File Format*, described in the *Introl Linker
and Loader Reference Manual*. Both are available at
<http://www.swtpc.com/mholley/Introl/>.

# Building and Installing

## Requirements

You need a C compiler and `make`. Building this manual also needs
`pandoc` and a LaTeX installation (see Section \ref{building-the-manual}).

## Building

From the top of the source tree:

```
$ make
```

This builds `ar/ar01`, `as/as01`, `ld/ld01`, `ld/objdump01` and
`ld/objcopy01`. The build stops at the first error.

## Installing

```
$ sudo make install
```

All the programs are installed into a single directory, by default
`/usr/local/m6801-tools`. `nm01` and `size01` are created there as
links to `objdump01`. The manual pages are installed into
`/usr/local/share/man/man1`. To choose other directories, set `PREFIX`
for the programs and `MANDIR` for the manual pages; to stage the files
for packaging, set `DESTDIR` as well:

```
$ make install PREFIX=/opt/m6801
$ make install DESTDIR=/tmp/pkgroot PREFIX=/usr/bin MANDIR=/usr/share/man
```

Add the installation directory to your `PATH`:

```
$ export PATH=$PATH:/usr/local/m6801-tools
```

## Manual pages

Each tool has a manual page in `doc/man`. `make install` installs them
(see above), with `nm01` and `size01` as links to the `objdump01`
page. To install only the manual pages, use:

```
$ sudo make install-man
$ man as01
```

You can also read one without installing it, using `man -l doc/man/as01.1`.

## Building the manual {#building-the-manual}

This manual is built from `doc/manual.md`, with the command reference
generated from the manual pages and the instruction table generated by
running the assembler:

```
$ make            # build the tools first
$ cd doc
$ make
```

# Getting Started

This chapter builds a small program for the Tandy MC-10, which has an
MC6803 processor. The program prints a message on the screen using the
character output routine in the MC-10 ROM, whose address is stored at
`$FFDE`.

Save this as `hello.s`:

```
; hello.s - print a message on the MC-10 screen
        LOC     0
        ENTRY   start

start   ldx     #msg
loop    ldaa    ,x              ; next character
        beq     done            ; zero byte ends the string
        inx
        pshx
        ldx     $ffde           ; ROM character output routine
        jsr     ,x
        pulx
        bra     loop
done    rts

msg     fcc     "HELLO, WORLD!"
        fcb     $0d,0
```

Labels start in column 1; instructions are indented. `ENTRY start`
marks `start` as the place where the program begins.

**Assemble** the source into an object module:

```
$ as01 -o hello.o hello.s
```

**Link** it. MC-10 machine language programs are commonly loaded at
`$434C`, just above the BASIC program area. The linker's `-T` option
sets the start address. Like all addresses given to the tools, it is
read like a C number, so write hexadecimal with `0x`:

```
$ ld01 -T0x434c -o hello.aout hello.o
```

**Convert** the result into a cassette audio file. `objcopy01` finds
the load address in the executable, and `-n` sets the name that the
MC-10 shows when it loads the file:

```
$ objcopy01 -O wav -n HELLO hello.aout hello.wav
```

Play `hello.wav` into the MC-10's cassette input (or load it into an
emulator), type `CLOADM`, and then `EXEC` to run the program.

To see what the assembler produced, ask for a listing with `-l`:

```
$ as01 -o hello.o -l hello.lst hello.s
```

```
00005 0000   CE   0012> start	ldx	#msg
00006 0003   A6     00  loop	ldaa	,x		; next character
00007 0005   27     0A  	beq	done		; zero byte ends the string
...
00016 0012          48  msg	fcc	"HELLO, WORLD!"
```

The columns are the line number, the address, the opcode and the
operand bytes. A `>` after the operand means the value is relocatable
and will be adjusted by the linker. Here `msg` is at offset `$0012`
from the start of the module, and becomes `$435E` once linked at
`$434C`. `fcc` and `fcb` lines show only the first byte.

# The Assembler

## Invoking as01

```
as01 [-gkuw] [-b binfile] [-l [listfile]] [-m [listfile]] [-n name]
     [-o objfile] [-s symfile] [-t n] [srcfile]
```

| Option | Meaning |
|:-------|:--------|
| `-o objfile` | Write a relocatable object file |
| `-b binfile` | Write an absolute binary image (see Section \ref{absolute-programs}) |
| `-l [listfile]` | Write a listing to *listfile*, or to standard output |
| `-m [listfile]` | List macro expansions in full (see Section \ref{listings-and-symbol-files}) |
| `-s symfile` | Write a symbol table file |
| `-n name` | Module name to store in the object file (default: from the source file name) |
| `-g` | Put only global symbols in the object file |
| `-u` | Treat undefined symbols as imported |
| `-w-` | Enable warnings (they are off by default) |
| `-k` | Keep output files even if there are errors |
| `-t n` | Put `.TEXT` sections in location counter *n*+3 |

Each option must be a separate argument (write `-g -u`, not `-gu`).
Only one source file may be given; if there is none, the source is read
from standard input. If there are errors, the object and binary files
are deleted (unless `-k` is given) and `as01` exits with status 1.

## Source lines

Each line has up to four fields:

```
[label[:]]   [operation   [operands]]   [; comment]
```

* A **label** without a colon must start in column 1. A label followed
  by a colon may be indented.
* The **operation** is an instruction mnemonic, a directive or a macro
  name. It must be preceded by white space unless it follows a label.
* **Operands** are separated by commas.
* A **comment** starts with `;` or `!`. A line whose first character is
  `*`, `;` or `!` is a comment line. Blank lines are allowed.

A line consisting only of a label defines the label at the current
address. If the assembler finds a word it doesn't know where an
operation should be, it reports `opcode expected`.

```
* A comment line
table   fcb     1,2,3           ; label in column 1
        ldaa    table           ; instruction, indented
next:   inca                    ; label with colon
here                            ; label alone
```

## Symbols

Symbols are made of letters, digits, `_` and `.`, and must not start
with a digit. They are case sensitive: `Loop` and `loop` are different.

Mnemonics, directives and register names are recognized in all upper
case or all lower case (`LDAA` or `ldaa`, but not `LdAa`). They cannot be
used as labels. The register names are `A`, `B`, `D` and `X`.

## Constants

| Form | Meaning |
|:-----|:--------|
| `123` | Decimal |
| `$7F` or `0x7F` | Hexadecimal |
| `0177` | Octal (any number with a leading zero) |
| `%1010` | Binary |
| `'A` or `'A'` | Character code |

## Expressions

From lowest to highest precedence, the expression operators are:

  Operators                   Meaning
  --------------------------  ---------------------------------------------
  `=`  `<`  `>`               Comparison: true is -1 (`$FFFF`), false is 0
  `+`  `-`  `|`               Addition, subtraction, bitwise OR
  `*`  `/`  `&`  `<<`  `>>`   Multiplication, division, bitwise AND, shifts
  `-`  `+`  `~`               Unary minus, unary plus, bitwise complement
  --------------------------  ---------------------------------------------

Use parentheses to group subexpressions. A `*` where an operand is
expected stands for the current location counter, so `bra *` is an
infinite loop.

A symbol is *absolute* if it has a fixed value (a constant, or a label
after `ORG` in a non-relocatable program) or *relocatable* if its value
depends on where the linker puts the module. You can add a constant to a
relocatable value or subtract two relocatable values from the same
section, but other combinations, such as adding two relocatable values,
are errors.

## Addressing modes

| Mode | Example | Notes |
|:-----|:--------|:------|
| Inherent | `inx` | No operand |
| Immediate | `ldaa #$10` | `#` prefix; 16-bit for `LDD`, `LDX`, `LDS`, `CPX`, `ADDD`, `SUBD` |
| Direct | `ldaa $80` | Address in `$00`–`$FF`, one byte |
| Extended | `ldaa $1234` | Any 16-bit address |
| Indexed | `ldaa 5,x` | Unsigned 8-bit offset (0–255) from X; `,x` means `0,x` |
| Relative | `bne loop` | Branches; target within -128 to +127 bytes |

The assembler chooses between direct and extended addressing on its
own. It uses direct addressing when the address is known in the first
pass and is in `$00`–`$FF`. Forward references and relocatable
addresses always use extended addressing. You can force the choice by
writing `<` (direct) or `>` (extended) before the operand:

```
        ldaa    <port           ; direct, even if port is defined later
        ldaa    >$0080          ; extended, even though $80 fits in a byte
```

The MC6801 has no direct mode for the read-modify-write instructions
(`NEG`, `COM`, `LSR`, `ROR`, `ASR`, `ASL`/`LSL`, `ROL`, `DEC`, `INC`,
`TST`, `CLR`) or for `JMP`. These always use extended addressing for
non-indexed operands, and `<` is an error with them.

The MC6801 has 128 bytes of internal RAM at `$0080`–`$00FF` and its
I/O registers at `$0000`–`$001F`. Define symbols for them *before*
using them, so that the assembler can use direct addressing:

```
PORT1   equ     $02
RAM     equ     $80

        ldaa    PORT1           ; direct: 96 02
        clr     RAM             ; extended: 7F 0080 (no direct CLR)
```

## Instruction set

`as01` accepts the full MC6801/MC6803 instruction set, using the
mnemonics from the Motorola data sheet. Appendix \ref{opcode-table}
lists every instruction with its opcodes. Some instructions have two
names:

| Name | Same as |
|:-----|:--------|
| `CMPX` | `CPX` |
| `LSL`, `LSLA`, `LSLB`, `LSLD` | `ASL`, `ASLA`, `ASLB`, `ASLD` |
| `BHS` | `BCC` |
| `BLO` | `BCS` |

## Directives

Directives (also called pseudo-ops) control the assembler. Many have
several names, for compatibility with other assemblers; they are
separated by `/` below.

### Defining data

| Directive | Meaning |
|:----------|:--------|
| `FCB`/`.BYTE`/`DB`/`.DATA1` *expr*,... | Bytes |
| `FDB`/`.WORD`/`DW`/`.SHORT`/`.DATA2` *expr*,... | 16-bit words, high byte first |
| `FCC`/`.ASCII` *string* | Characters of a string |
| `.ASCIZ` *string* | Characters of a string, then a zero byte |
| `RMB`/`.BLKB`/`.SPACE` *count*[,*fill*] | Reserve *count* bytes; filled with *fill* if given |
| `.BLKW`/`.ZEROW` *count* | Reserve *count* words |

A string starts with a delimiter character and ends at the next
occurrence of it, so `"text"`, `/text/` and `'text'` are all valid. Two
delimiters in a row stand for one delimiter character. These C escape
sequences are recognized: `\n`, `\r`, `\t`, `\a`, `\b`, `\f`, `\v`,
`\\`, `\'`, `\"`, `\?` and octal `\0` to `\377`.

```
msg     fcc     "Hello"
        fcb     $0d,0
name    .asciz  /MC-10/
table   fdb     start,stop,$1000
buffer  rmb     32              ; 32 bytes, not initialized
spaces  rmb     8,$20           ; 8 bytes containing $20
```

### Defining symbols

| Directive | Meaning |
|:----------|:--------|
| *label* `EQU` *expr* | Define a constant |
| *label* `=` *expr* | Same as `EQU` |
| *label* `SET` *expr* | Define a symbol that can be redefined later |
| `EXPORT`/`PUBLIC`/`.DEFINE` *sym*,... | Make symbols visible to other modules |
| `ENTRY` *sym* | Export *sym* and mark it as the program entry point |
| `IMPORT`/`EXTERN`/`.EXTERN`/`EXTRN` *sym*,... | Use symbols from other modules |
| `.GLOBL`/`.GLOBAL` *sym*,... | Export if defined here, otherwise import |
| *label* `COMM` *size* | Common block of *size* bytes, shared between modules |
| *label* `LCOMM` *size* | Common block local to this module |
| `.COMM`/`.LCOMM` *name*,*size* | Unix-style forms of the above |


### Location and sections

| Directive | Meaning |
|:----------|:--------|
| `LOC` *n* | Switch to location counter *n* (0–15) |
| `.TEXT` | Switch to location counter 0 |
| `.DATA`, `.ROM`, `.BSS` | Switch to location counter 3 |
| `.SECT` *name* | Switch to section `.text`, `.data` or `.bss` |
| `ORG` *expr* | Set the location counter to *expr* |
| `BLOCK` *expr* ... `ENDB` | Assemble the enclosed lines at *expr*, then return to the previous location |
| `.ALIGN` *n* | Advance to a multiple of *n* |
| `.EVEN` | Advance to an even address |

Section \ref{location-counters-and-segments} explains how the location
counters are mapped into memory.

### Conditional assembly

| Directive | Meaning |
|:----------|:--------|
| `IF` *expr* | Assemble the following lines if *expr* is non-zero |
| `IFC` (*str1*,*str2*) | Assemble the following lines if the strings are identical |
| `ELSEIF` *expr*, `ELSEIFC` (*str1*,*str2*) | Alternative conditions |
| `ELSE` | Assemble if no earlier condition was true |
| `ENDIF` | End of the conditional block |

Conditionals may be nested. Conditions should only use symbols defined
earlier in the source.

```
DEBUG   equ     1

        IF      DEBUG
        jsr     dump_registers
        ELSE
        nop
        ENDIF
```

### Macros

A macro is defined with `MACRO` *name* and ends with `MEND`. Inside the
body, `?1`, `?2`, ... are replaced by the arguments of the call. The
arguments are separated by commas.

```
        MACRO   store2          ; store A and B at two addresses
        staa    ?1
        stab    ?2
        MEND

        store2  $1000,$1002
```

A macro must be defined before it is used. Within a macro, `IFC` can
test the arguments, for example `IFC (?1,)` to check whether the first
argument is empty.

### Other directives

| Directive | Meaning |
|:----------|:--------|
| `INCLUDE`/`GET` *file* | Assemble the contents of *file* at this point |
| `END` | End of the source; anything after it is ignored |
| `FAIL` | Report an error (useful in conditionals) |
| `.LIST`, `.MACLIST` [*n*] | Turn listing or macro listing on and off (only when `-l` or `-m` is used) |
| `.WARN` [*n*] | Turn warnings on (`.WARN 1`) and off again (`.WARN`) |

## Listings and symbol files {#listings-and-symbol-files}

`-l` writes a listing with the source, the address and the generated
bytes, followed by a symbol table and the number of errors and
warnings (see the example in Chapter 3). The instructions generated by
macro calls are listed after the call, marked with `+a`.

`-m` lists every line of each macro expansion, including directives and
lines skipped by conditionals. On its own it lists only the macro
expansions; use `-l -m listfile` to get the full listing as well.

In the listing's symbol table, each symbol is followed by its location
counter number, its value, `A` (absolute) or `R` (relocatable), and
`E` (exported), `I` (imported), `N` (entry point) or `C` (common).

`-s` writes a symbol file with one line per symbol: the counter, the
value, five flag columns (`E` exported, `N` entry, `I` imported, `R` or
`A`, `C` common) and the name:

```
0 0000 --IR- ext
0 000C EN-R- here
```

## Absolute programs {#absolute-programs}

For a simple program you can skip the linker entirely. Use `ORG` to set
the address and `-b` to write the binary image:

```
        org     $e000
reset   lds     #$00ff
        ...
        org     $fffe
        fdb     reset           ; reset vector
```

```
$ as01 -b rom.bin rom.s
```

The image starts at the lowest address assembled and ends at the
highest, so this example produces an 8 KB file covering `$E000` to
`$FFFF`. Gaps between `ORG` areas are filled with zeros. `IMPORT` and
other external references are not allowed with `-b`.

## Error messages

Errors are shown in the listing under the line that caused them, with a
`^` pointing at the position. If no listing file was requested, the
offending lines and the totals are printed on standard output. Some
common messages:

| Message | Usual cause |
|:--------|:------------|
| `opcode expected` | Misspelled or unknown instruction, or a label that isn't in column 1 |
| `undefined label` | A symbol is used but never defined or imported |
| `redefined label` | The same label is defined twice |
| `illegal address mode` | The instruction has no such addressing mode, such as `staa #1` or `clr <$80` |
| `address out of bounds` | Branch target too far away, or indexed offset outside 0–255 |
| `data out of bounds` | Value too large for a byte |
| `junk after operands` | Extra text after the operands; comments must start with `;` |
| `register used as identifier` | `A`, `B`, `D` or `X` used as a label |
| `absolute expression required` | A relocatable value where a constant is needed |
| `no imports with binary file output` | `IMPORT` used together with `-b` |
| `short branch would do` | (warning) a `JSR`/`JMP` target is close enough for a `BSR`/`BRA` |

# Modules and Linking

## Exporting and importing symbols

Each source file is assembled into an object module. By default, its
symbols are private. To share them:

* In the module that defines a symbol, name it in an `EXPORT` (or
  `ENTRY`) directive.
* In each module that uses it, name it in an `IMPORT` directive.

```
; screen.s                      ; main.s
        LOC     0                       LOC     0
                                        IMPORT  clrscn
clrscn  ldx     #$4000                  ENTRY   start
        ...                     start   jsr     clrscn
        rts                             rts
        EXPORT  clrscn
```

The linker reports `undefined symbol` for any import that no module
exports.

Exactly one module should contain an `ENTRY` directive. The linker uses
the first entry symbol it finds as the program's starting address, and
fails with `no start symbol` if there is none.

## Location counters and segments {#location-counters-and-segments}

The assembler keeps 16 independent location counters, numbered 0 to
15, selected with `LOC` or with `.TEXT`, `.DATA` and `.BSS`. Code
assembled under different counters is kept apart, even if the source
switches between them, and each module's counters start at 0.

The linker gathers all modules' counters into two segments:

| Counters | Segment |
|:---------|:--------|
| 0 and 1 | Text, placed at the `-T` address |
| 2 to 15 | Data, placed after the text, or at the `-D` address |

`.TEXT` selects counter 0, and `.DATA`, `.ROM` and `.BSS` all select
counter 3. If counter 2 would cross a 256-byte page boundary, the
linker moves it to the start of the next page.

Most MC6801 programs need only counter 0. Start each module with
`LOC 0` (or `.TEXT`) to make this explicit.

## Invoking ld01

```
ld01 [-dimMrsty] [-o outfile] [-T textaddr] [-D dataaddr] [-H heapsize]
     [-Ccrt] [-Llibdir] [-llib] [-Olibfile] file ...
```

| Option | Meaning |
|:-------|:--------|
| `-o outfile` | Output file name (default `a.out`) |
| `-T addr` | Text segment address |
| `-D addr` | Data segment address |
| `-H size` | Add *size* to the end of the program for `__heap_top` |
| `-Cname` | Link the start-up module `crtname.o` |
| `-lname` | Search the library `libname.a` |
| `-Ldir` | Add a library directory |
| `-Ofile` | Link *file*, looking in the library directories |
| `-d` | Write a raw memory image with no header or symbols |
| `-s` | Leave out the symbol table |
| `-m` | List the modules linked |
| `-M` | List all symbols with their values |
| `-r` | Combine the input objects into an archive instead of linking |
| `-i` | Mark the executable as having separate instruction and data spaces |
| `-t` | Trace modules as they are read (must come before the input files) |

The order of objects and libraries on the command line does not matter:
the linker reads them all before resolving symbols.

Addresses and sizes are read like C numbers: hexadecimal with a `0x`
or `$` prefix, octal with a leading `0`, and decimal otherwise. So
`-T0x1000`, `-T'$1000'` and `-T4096` all mean `$1000` (quote `$` from
the shell). Anything else, such as `-TE000`, or a value above `$FFFF`,
is an error. `objcopy01` reads its `-T` and `-D` options the same way.

## Output

The linker normally writes an a.out file: a 32-byte header
(Appendix \ref{a.out-format}), the text segment, the data segment and a
symbol table. `objcopy01` converts this into the format your target
needs (Chapter \ref{converting-executables}).

With `-d`, the output is a raw memory image containing just the text
segment followed by the data segment, ready to be burned into an EPROM:

```
$ ld01 -d -T0xe000 -o rom.bin start.o main.o
```

## Start-up modules

A *start-up module* is code that must run first: setting up the stack,
clearing memory, then calling the main program. By convention it is
called `crtname.o` (from "C run-time") and linked with `-Cname`:

```
; crtstart.s
        LOC     0
        IMPORT  main
        ENTRY   __start
__start lds     #$00ff
        jsr     main
        rts
```

```
$ as01 -o crtstart.o crtstart.s
$ ld01 -Cstart -T0x434c -o prog.aout main.o
```

## Libraries

`-lname` links the needed members of the archive `libname.a`. An
archive member is linked only if it defines a symbol that something else
being linked uses. See Chapter \ref{libraries-chapter} for how to build
libraries.

Files named with `-C`, `-l` and `-O` are searched for in the `-L`
directories (up to five), most recent first. There is no default
library directory. If they are not found, the name is tried as given,
in the current directory.

## Linker symbols

The linker defines these symbols, which a program can `IMPORT`:

| Symbol | Value |
|:-------|:------|
| `__btext`, `__etext` | Start and end of the text segment |
| `__bdata`, `__edata` | Start and end of the data segment |
| `__end` | End of the program, including uninitialized data |
| `__heap_top` | `__end` plus the `-H` value |

For example, a start-up module can clear uninitialized data between
`__edata` and `__end`.

`__btext`, `__etext`, `__bdata`, `__edata` and `__end` are always
written to the executable's symbol table (unless `-s` is used), where
`objcopy01` finds the load addresses.

## Link maps

`-m` prints a line for each module: `+` if it was linked, `-` if it is
an archive member that was not needed. `-M` prints every symbol with
the module that defines it, its value and its type:

```
$ ld01 -lnum -Cstart -T0x434c -m -M -o main.aout main.o screen.o
one             +libnum.a(one.o)
crtstart        +crtstart.o
main            +main.o
screen          +screen.o
                 one                   one  0  00004351  R
            crtstart               __start  0  00004380  R N
              screen                SCREEN  0  00004000  a
...
Total memory used: 000004ff
```

# Libraries {#libraries-chapter}

A library is an archive of object modules, created and maintained with
`ar01`. The usual name is `libname.a`, so that it can be linked with
`-lname`.

```
$ ar01 rc libnum.a one.o two.o three.o        # create or update
$ ar01 t libnum.a                             # list members
one.o
two.o
three.o
$ ar01 d libnum.a two.o                       # delete a member
$ ar01 x libnum.a one.o                       # extract a member
```

| Key | Operation |
|:----|:----------|
| `r` | Replace or add members (creates the archive if necessary) |
| `q` | Append members without checking for duplicates |
| `d` | Delete members |
| `m` | Move members (to the end, or with `a`/`b` next to another member) |
| `t` | List members (`tv` for details) |
| `x` | Extract members |
| `p` | Print members to standard output |

Modifiers: `c` (create silently), `v` (verbose), `u` (replace only
newer files), `o` (keep dates on extraction), `a`/`b`/`i` *posname*
(position), and `s`, which adds a `__.SYMDEF` index of the symbols each
member exports. The linker doesn't need the index, since it reads every
member's symbols itself, but it does no harm.

Put each routine that may be needed separately in its own module, so
that the linker includes only what a program uses.

# Inspecting Object Files and Executables

`objdump01` shows the header, segment sizes, symbol table and a hex dump
of an a.out executable:

```
$ objdump01 main.aout
OBJECTFILE 'main.aout'
HLEN 32
CPU  m6801 BIG_ENDIAN
FLAGS: A_EXEC
a_entry  = 0x00004380
a_total  = 0x0000006c
a_syms   = 0x00000130

text    data    bss     dec     hex     filename
108     0       0       108     6c      main.aout

SYMBOLS
0000434c t msg_one
00004351 T one
...
TEXTSEG
: 4f 4e 45 0d 00 ce 43 4c  3c bd 43 a5 31 31 39 00  ONE...CL<.C.119.
...
```

`nm01` (or `objdump01 -n`) prints only the symbols, and `size01` (or
`objdump01 -s`) only the sizes:

```
$ size01 main.aout
text    data    bss     dec     hex     filename
108     0       0       108     6c      main.aout
$ nm01 main.aout
0000434c t msg_one
00004351 T one
00004380 T __start
00004000 a SCREEN
...
```

In the symbol list, `T`/`t` are text symbols, `D`/`d` data symbols,
`C`/`b` bss or common symbols and `a` absolute symbols. Upper case means
global, lower case local, and `U` marks a symbol that is used but not
defined. Symbol names in executables are cut to 8 characters.

The same tools work on object files made by `as01`, and on libraries
made by `ar01`, which shows each module in turn. For an object file,
`objdump01` shows the module's symbols, its size, and its code with the
relocation records that `ld01` uses to fill in addresses:

```
$ objdump01 main.o
OBJECTFILE 'main.o'
MODULE  'main'
...
SYMS 6
SYM 0    00000000 ..E.T main
SYM 1    00000000 ...IT three
...
BYTECODE
SEG 0
: bd                                                .
RELSZ 2
DW clrscn
...
$ nm01 main.o
00000000 T main
         U three
         U one
...
```

Here `DW clrscn` means that the two bytes after the `jsr` opcode
(`bd`) are filled in with the address of `clrscn`. In object files,
location counters 0 and 1 count as text and the others as data, as
they are linked by `ld01`.

# Converting Executables {#converting-executables}

`objcopy01` turns an a.out file into a format that a loader, EPROM
programmer, emulator or cassette interface can use:

```
objcopy01 [-O format] [-T textaddr] [-D dataaddr] [-n name] [-p]
          infile outfile
```

| Format | Output |
|:-------|:-------|
| `binary` | Raw image: text, then data (`-p` pads to put data at its address) |
| `srec` | Motorola S-records (S0 name, S1 data, S5 count, S9 entry point) |
| `ihex` | Intel hex, with the entry point in the end record |
| `wav` | Cassette audio: 8-bit mono WAV at 43200 Hz, Color BASIC/MC-10 format |
| `cas` | The same cassette data as a byte stream, for emulators |

The load addresses come from the `__btext` and `__bdata` symbols that
the linker writes to the executable, so you don't normally need to
give them. Use `-T` and `-D` to override them, or when the executable
was linked with `ld01 -s` and has no symbol table. Addresses are
written the same way as for `ld01`: `0x434c` or `'$434c'` for
hexadecimal, plain digits for decimal.

The entry point is taken from the executable header. `-n` sets the name
stored in S-record headers and cassette files (up to 8 characters for
cassettes); without it, the output file name in upper case is used.

```
$ objcopy01 -O srec -n ROM rom.aout rom.s19
$ objcopy01 -O wav -n GAME game.aout game.wav
$ objcopy01 -O srec -T 0xe000 -n ROM stripped.aout rom.s19
```

The cassette formats require the data segment to follow the text
segment directly (no `-D`).

# A Worked Example

The `demo` directory contains a small modular program for the MC-10.
It shows modules, a library and a start-up module working together.
With the tools installed and on your `PATH`, build it with:

```
$ cd demo
$ make
```

## Modules

`screen.s` provides two subroutines, `clrscn` and `prstring`, and
exports them:

```
LOC 0

SCREEN  equ     $4000

clrscn  ldx     #SCREEN
        ldaa    #$40+'
        ldab    #$40+'
clrsc.1 std     ,x
        inx
        inx
        cpx     #(SCREEN+512)
        blt     clrsc.1
        rts

        EXPORT  clrscn

prstring
        tsx
        ldx     2,x
prstlop ldaa    ,x
        beq     prstxit
        inx
        pshx
        ldx     $ffde
        jsr     ,x
        pulx
        bra     prstlop
prstxit rts

        EXPORT  prstring
```

`prstring` takes a pointer to the string on the stack. `tsx` points X
at the top of the stack, and `ldx 2,x` loads the argument, which is
just above the return address.

## A library

`one.s`, `two.s` and `three.s` each print a word. Here is `one.s`:

```
LOC 0

        IMPORT  prstring

msg_one fcb     'O,'N,'E,$0d,$00

one
        ldx     #msg_one
        pshx
        jsr     prstring
        ins
        ins
        rts

        EXPORT  one
```

They are assembled and collected into `libnum.a`:

```
$ as01 -o one.o one.s
$ as01 -o two.o two.s
$ as01 -o three.o three.s
$ ar01 r libnum.a one.o two.o three.o
```

## The start-up module and main program

`crtstart.s` contains the entry point and calls `main`:

```
LOC 0

        IMPORT  main

        ENTRY   __start

__start
        jsr     main
        rts
```

`main.s` uses the routines from `screen.o` and the library:

```
LOC 0

        IMPORT  clrscn
        IMPORT  prstring

        IMPORT  one
        IMPORT  two
        IMPORT  three

main
        jsr     clrscn

        jsr     one
        jsr     two
        jsr     three
        rts

        EXPORT  main
```

## Linking and converting

```
$ ld01 -lnum -Cstart -T0x434c -o main.aout main.o screen.o
$ objcopy01 -T0x434c -O wav main.aout main.wav
```

The linker pulls in `crtstart.o` because of `-Cstart`, and `one.o`,
`two.o` and `three.o` from `libnum.a` because `main.o` uses them. Load
`main.wav` on the MC-10 with `CLOADM` and run it with `EXEC`.

# Known Limitations

* **Symbol names are cut to 8 characters** in executables.
* **Warnings are off by default**; use `as01 -w-` or `.WARN 1`.
* **Version messages** (`-v`) still name the original `as86` and `ld86`.
